## Reading guide

### Severity legend
- **CRITICAL** — missing content that blocks the zone from working (empty `direct_answer`, missing `speakable_answer`, missing `key_points`, stub question).
- **MAJOR** — structural problem like duplicate/overlapping topics across a module.
- **MODERATE** — substantive content gap that degrades the zone (e.g. long Zone 3 with zero code, direct_answer paragraph wall with no bold anchors).
- **MINOR** — polish-level issue (missing bold anchors on a short answer, thin key_points, no analogy detected, etc.).
- **CLEAN** — no structural signal triggered; still subject to judgment-layer review.

### What each report contains
- **Module-level structural issues** — stubs + detected topic overlaps.
- **Per-topic question tables** — Zone 1 / Zone 2 / Zone 3 issue summary per question plus worst-severity label.
- **Tally** — count by severity + most common issue codes.

### Structural vs curated
- `*_structural.md` files are auto-generated from the v3 auditor and flag deterministic signals (missing zones, missing code, paragraph walls, thin key points, speakable shape, interviewer_intent completeness, slug-based overlap).
- Files without the `_structural` suffix are hand-curated with internet-tone calibration, analogy gap analysis, standard-interview-fact coverage, and topic-overlap judgment. These supersede the matching structural report for that module.

- `spring-webflux`, `application-security`, `advanced-testing`, `cloud-native`, `engineering-practices` — these need content authored from scratch, not audited.
